# D2 diagrams

The /files viewer renders ` ```d2 ` fences with the d2 version pinned in
`frontend/package.json`. `@d2lang/d2` — the WASM engine, its web worker,
and the fonts — travels in one lazy chunk. Every diagram gets pan/zoom
controls (+/−/1:1 buttons, ctrl/cmd+wheel, pinch). Engine and themes are
set in code (`frontend/src/system/components/d2.ts`); this build ignores the
language's `vars:` block, so don't write one.

**Validate before deploying** — `./run checkmarkdownd2 <file.md>`
compiles every fence in one file with that exact build and shows the
first broken block on failure; the same run renders each fence to
fence<N>.svg in a fresh /tmp/desmo/ dir (the reviewer's input). No args
on a TTY scans every fence in the default docs. A broken diagram
otherwise shows as raw source in the
browser. Full grammar lives at d2lang.com; this page carries the
constructs feature docs use — every fence below follows the validated
shapes (copy them as the starting point, don't recompose from memory).

## The one layout rule

`direction: down` at the top of every flow diagram, and keep containers
narrow. (d2's default is down — the directive documents intent.) Wide
left-to-right layouts overflow a phone screen; vertical flows fit the
column. D2 renders SVGs that fit to width by default, and pan/zoom covers
the rest — but a tall diagram reads better than a wide one at every size.

Inside containers `direction` is IGNORED — an inner `direction: down`
changes nothing, and unconnected members default to side-by-side. Two
ways to stack an inner block vertically:

- chained members flow down on their own — `a -> b -> c` stacks
  without any directive;
- unconnected members need a grid — `grid-rows: N; grid-columns: 1`
  (the use-case fences below use this).

```d2
direction: down
audit: Nightly audit {
  snapshot: Snapshot the catalogue
  compare: "Compare with\nlast night's snapshot"
  report: "Email the librarian\nthe differences"
  snapshot -> compare
  compare -> report
}
```

The engine never wraps labels — each renders as ONE line at its natural
width, so a long label overflows any fixed node width (a 240px oval
with a 240px label pokes past the curve). Keep labels short or embed
the breaks yourself: `"See the due summary\non the homepage"`.

## Use-case diagrams

- Actors as `shape: person`, **pinned to `width: 180; height: 160`** —
  every actor renders identically.
- Use cases as fixed `width: 240`:
  - a literal `shape: oval` only when the label is short enough to
    clear the curve;
  - otherwise a rounded box (`style.border-radius: 24`) with the
    breaks embedded.
- The system boundary as a container, stacked with a grid.

```d2
direction: down
visitor: Anonymous visitor {shape: person; width: 180; height: 160}
member: Library member {shape: person; width: 180; height: 160}
member -> visitor: is a
library: Library {
  grid-rows: 3
  grid-columns: 1
  search: Search the catalogue {shape: oval; width: 240}
  borrow: Borrow a book {shape: oval; width: 240}
  reserve: "Reserve a copy\nwhen none are on shelf" {width: 240; style.border-radius: 24}
}
visitor -> library.search
member -> library.borrow
member -> library.reserve
note: Anonymous visitors can only search. {shape: text}
note.near: bottom-center
```

Include/extend semantics ride dashed labeled arrows between two uses:

```d2
direction: down
borrow: Borrow a book {shape: oval}
search: Search the catalogue {shape: oval}
borrow -> search: include {style.stroke-dash: 3}
```

Back-office maintenance gets its own fence — a separate actor, a
separate boundary, and a note stating who is kept out:

```d2
direction: down
librarian: Librarian {shape: person; width: 180; height: 160}
upkeep: Catalogue upkeep {
  grid-rows: 3
  grid-columns: 1
  add: "Add a book\nto the catalogue" {width: 240; style.border-radius: 24}
  withdraw: Withdraw a worn copy {shape: oval; width: 240}
  suspend: "Suspend a member\nwith overdue loans" {width: 240; style.border-radius: 24}
}
librarian -> upkeep.add
librarian -> upkeep.withdraw
librarian -> upkeep.suspend
note: Librarian-only — hidden from members. {shape: text}
note.near: bottom-center
```

- Role inheritance: an arrow between two actors, labeled
  `member -> visitor: is a`.
- Permission notes: a `{shape: text}` shape near the boundary ("gets a
  404", "no sign-in needed") with `note.near` — the plain-language front
  of the doc states permissions; the diagram shows them.
- At most a handful of uses per boundary row — the grid stacks them.

## Data diagrams

Entities as `shape: sql_table` — the table card carries columns and types.
Foreign keys are column-to-column arrows; cardinality and the delete rule
are the arrow's label (plain text beats crow's-foot glyphs for the
plain-language audience).

```d2
direction: down
member: Member {
  shape: sql_table
  name: text
}
book: Book {
  shape: sql_table
  title: text
  author: text
  withdrawn: yes/no
}
loan: Loan {
  shape: sql_table
  book: Book
  by: Member
  on: date
  returned: date?
}
loan.by -> member: "by (N..1) · on delete RESTRICT"
loan.book -> book: "of (N..1) · on delete RESTRICT"
```

## State diagrams

States as shapes, transitions as labeled arrows, the initial state as a
small circle. `direction: down` keeps the flow phone-friendly.

```d2
direction: down
initial: {shape: circle}
available: available — on the shelf
borrowed: borrowed — out with a member
withdrawn: withdrawn — removed from circulation
initial -> available: acquired
available -> borrowed: borrowed
borrowed -> available: returned
available -> withdrawn: withdrawn
```

## Scheduled flows

Backend maintenance renders as a chained a→b→c flow — a trigger shape,
then the steps in order, one statement per line. Long labels carry
their own breaks.

```d2
direction: down
timer: Midnight timer {shape: circle}
snapshot: Snapshot the catalogue
compare: "Compare with\nlast night's snapshot"
report: "Email the librarian\nthe differences"
timer -> snapshot: fires
snapshot -> compare
compare -> report
```

## Icons

Optional. Keep icons LOCAL — the app's CSP loads no remote images:

- Pick a lucide name by grepping
  `frontend/node_modules/lucide-static/icons/` (a devDependency — the
  full set is offline).
- Copy the SVG to `djangoapp/static/icons/`, setting a concrete stroke
  color and width in the file — external SVGs cannot inherit page CSS,
  so `currentColor` renders black.
- Reference it by URL: `icon: /static/icons/<name>-<hex>.svg`.

```d2
api: API server {icon: /static/icons/server-0a1f44.svg}
member: Library member {shape: person; icon: /static/icons/user-0a1f44.svg}
member -> api
```
