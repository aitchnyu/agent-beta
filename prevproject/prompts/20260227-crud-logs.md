### Architecture Overview

The CRUD logs system consists of:

1. **CrudUpdate Model** (`djangoapp/models.py`) [crud-update-model-arch]
   - Stores audit trail for create/update/comment actions
   - JSON field `_values` with pydantic-based serialization/deserialization via `values` property [crud-update-values-property-arch]
   - Indexed by `modelname` and `pk` for efficient querying [crud-update-indexes-arch]
   - No direct FK relationship to avoid cascading issues [no-fk-relationship-arch]

2. **CrudLogPermissionContext** (`djangoapp/models.py`) [crud-log-permission-context-arch]
   - Dataclass for permission resolution context
   - Contains `user` and `entity` (either "list" or model instance)

3. **Permission System** (`djangoapp/models.py`) [permission-system-arch]
   - `crud_log_permission` classmethod on BaseBaseModel [crud-log-permission-method-arch]
   - Returns one of: `none`, `redacted`, `unredacted`, `full` [permission-levels-arch]
   - Default is `full` for backward compatibility

4. **Filter Integration** (`djangoapp/views.py`) [filter-integration-arch]
   - New CrudUpdateFilter for list page filtering [crud-update-filter-arch]
   - Subquery-based filtering for efficiency

5. **API Endpoints** (`djangoapp/views.py`) [api-endpoints-arch]
   - `GET /tables/{model}/row-crud-updates/{row_id}` - List CrudUpdates for a row (eagerly loaded in details) [api-list-endpoint]
   - `POST /tables/{model}/add-comment/{row_id}` - Add a comment [api-add-comment-endpoint]
   - `POST /tables/{model}/delete-comment/{crud_update_id}` - Delete a comment [api-delete-comment-endpoint]

6. **Frontend Components** (`frontend/src/`) [frontend-components-arch]
   - CrudUpdateList.vue - Display updates/comments with filter buttons [crud-update-list-component]
   - CrudUpdateFilter.vue - Filter widget for list page [crud-update-filter-component]
   - CommentForm.vue - Comment input [comment-form-component]
